Côte d'Ivoire · conseil agricole et élevage

AGROGUIDCI Un agent principal agronome, six spécialistes, une seule réponse — cohérente, prudente et traçable.

Le producteur formule une demande : l'Agent Agronome Expert clarifie le besoin, sélectionne les compétences utiles, délègue aux sous-agents, puis signe une réponse unique — avec ses chiffres vérifiés, ses limites déclarées et son journal de mission.

01La règle centrale

GOAL → PLAN → ACT → OBSERVE → DECIDE → ADAPT → VERIFY puis CONTINUE, STOP ou ESCALATE.

GOAL — clarifier le besoin PLAN — choisir les compétences ACT — agir ou déléguer OBSERVE — lire le résultat réel DECIDE — comparer à l'attendu ADAPT — une seule relance VERIFY — recalculer CONTINUE STOP ESCALATE

Le système ne se contente pas d'exécuter une tâche : il observe son propre résultat, détecte l'écart, cherche une alternative autorisée, adapte son plan, vérifie — ou passe la main à un humain.

02L'architecture

AGROGUIDCI est la plateforme. L'Agent Agronome Expert est le cerveau opérationnel : il traite l'agronomie en propre et coordonne. Les sous-agents ne sont convoqués que lorsqu'ils sont utiles à la demande.

03Ce que le système ne fera jamais

  • Prescrire un pesticide, un traitement ou un dosage.
  • Prescrire un médicament vétérinaire ou poser un diagnostic définitif.
  • Annoncer un prix de marché, un rendement garanti, un revenu promis.
  • Inventer une donnée, une source, une URL ou la sortie d'un outil.
  • Envoyer un message, publier, acheter, payer, supprimer à votre place.
  • Donner un conseil médical humain.
Ce qui n'est pas su est écrit noir sur blanc : FAIT, ORDRE DE GRANDEUR (à confirmer localement) ou INCONNU — et le renvoi se fait vers l'échelon local : ANADER, CNRA, MINADER, MIRAH, vétérinaire, coopérative.

Écrire dans une base persistante externeInterditHors périmètre sans droits accordés

Un outil exécuté ne signifie pas que la mission a réussi : chaque mission est recalculée indépendamment avant d'être remise, et une action sensible dépose une demande qu'un opérateur approuve — le résultat réel est relu avant d'être annoncé.

05Preuves d'exécution

TERMINEE_VERIFIEE

Mission cacao (Daloa, 3 ha) : marge recalculée indépendamment à l'identique — recette 1 350 000 FCFA − charges 500 000 = 850 000 FCFA, seuil 333,3 kg.

7 / 7 tests de rupture

Outil indisponible, données erronées, chemin inconnu, mission impossible, permission refusée, information manquante, intégration déconnectée — comportements attendus tenus.

Coherent

Contrôle automatique supervision.py --coherence : chaque agent documenté, chaque outil cité existe, chaque outil installé a un titulaire.

États finaux

TERMINEE_VERIFIEE, A_VALIDER, EN_ATTENTE_INFORMATION, ECHEC_OUTIL, ARRETEE_PERMISSION, ESCALADE_HUMAINE.

07Exécuter le système

python demarrer_agroguidci.py             # orchestrateur local + 7 agents
python coordinateur.py --demande "A Daloa, 3 ha de cacao, 900 kg a 1500 FCFA le kg..."
python supervision.py --etat              # agents réellement en ligne
python supervision.py --charte            # rôles, compétences, outils, actions sensibles
python supervision.py --coherence         # spec <-> agents <-> outils
python validation.py --lister             # actions sensibles en attente d'un humain
python tests_j2.py                        # les sept ruptures + rapport de preuves

Le système tourne en local : un orchestrateur FastAPI, sept agents Python, une base de connaissances agricole ivoirienne (agronomie, techniques culturales, production animale, services) et un journal de mission par demande.
